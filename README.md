# Аким на 5 часов — симулятор управления Астаной

Один математический движок и четыре объясняющие роли: Analytics & Math Engine, Astana Urban Expert, Social & Risk Agent и Akim Chief Advisor. Реализация находится в `akim_sim/`; `main.py` — удобная точка входа. Консоль и JSON API работают без веб-интерфейса.

## Запуск

Python 3.10+:

```bash
python -m venv .venv
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python main.py --input example_allocation.json --offline --json
python main.py --input example_measures.json --offline --json
python -m akim_sim --optimize
```

Для AI-объяснений скопируйте `.env.example` в `.env`, впишите `OPENAI_API_KEY` и уберите `--offline`. Ключ не попадает в репозиторий. Без ключа отчёт строят детерминированные правила; Score от наличия ключа не зависит. Модель OpenAI по умолчанию `gpt-4o-mini`; переопределение: `OPENAI_MODEL` или `--model`. Живой вызов API без пользовательского ключа не проверялся.

Для машинной интеграции добавьте `--json`, либо используйте `python -m akim_sim --serve` и `POST /score` (только числа) / `POST /simulate` (отчёт агентов). Сервер по умолчанию на `127.0.0.1:8000`; `/config`, `/validate` и `/optimal` помогают собрать интерфейс. Для доступа извне задайте Bearer-токен `AKIM_API_TOKEN`. Детали: [документация модели](docs/ADVANCED.md).

## Пять решений и одна шкала

- `allocation`: пять чисел `transport`, `green`, `social`, `safety`, `utilities` — **верхние лимиты** расходов по сферам. Их сумма ≤100. Алгоритм перебирает допустимые наборы и выбирает лучший из **ровно пяти целых мер** каталога M1–M14, не выходя за каждый лимит. Неиспользованная часть лимита видна в отчёте; она не превращается в эффект автоматически. Если пять мер невозможны, возвращается 422/код выхода 2 без Score.
- `measures`: пользователь сам выбирает пять уникальных мер и районы. Каталог ограничивает бюджет 100, максимум две меры в одной сфере и несовместимые пары. Некорректный план не оценивается; API возвращает все причины.

В обоих режимах используется одна формула (показатели и коэффициенты игрового датасета):

```text
I′[d,k] = clip(I[d,k] + Σ_m effect[m,k] · (8 − lag[m])/8 + synergy[d,k], 0, 100)
D[d]    = Σ_k weight[k] · I′[d,k]
D_avg   = Σ_d population_share[d] · D[d]
N_crit  = число пар (d,k), для которых I′[d,k] < 40
Score   = clip(0.7 · D_avg + 0.3 · min_d D[d] − N_crit, 0, 100)
```

Веса `T1,T2,E1,E2,S1,S2,B1,B2,C1,C2`: `0.10,0.10,0.09,0.11,0.11,0.11,0.09,0.09,0.10,0.10`. Три синергии каталога: M1+M2 даёт +2 к T1 в районе M1; M10+M12 даёт +2 к B1 в районе M10; M5+M6 даёт +2 к E2 в районе M5. Штраф перекоса **не придуман сверх датасета**: 30% итогового балла зависит от слабейшего района, каждый критический показатель снимает 1 балл, а избыточный лимит без подходящих мер не повышает Score. Клиппинг и ограниченный каталог дают насыщение эффекта; при синергии маржинальные приращения могут быть немонотонными, поэтому общую вогнутую функцию отдачи мы не заявляем.

База: **52.558**. Пример ручных мер: **56.543** за 95 ед. Лимиты 25/15/25/15/20: **56.015** за 85 ед. Глобальный оптимум пяти мер при бюджете 100: **57.237** за 98 ед. (полный перебор 694 395 допустимых размещений). Величины — условные игровые единицы, не смета в тенге.

## Проверка и ограничения

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q tests
```

Индексы аварий, заторов и недовольства — модельные прокси 0–100, не вероятности и не реальные сообщения жителей. Анализ чувствительности меняет веса показателей, а не симулирует буран или паводок. Данные и эффекты учебные; для городской политики нужны измерения и калибровка. Исходные ссылки организаторов: [описание кейса](https://docs.google.com/document/d/1oDZtYnBgbcn_Ii7vleP87hkARJ2HmbXl7Cw_rsCxqpo/edit), [датасет районов](https://docs.google.com/document/d/1Uc-GdGoKhDY-spu8V50-ZMm33t2CjYLP/edit).
