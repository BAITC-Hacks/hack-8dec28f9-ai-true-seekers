# Аким на 5 часов — запускаемый симулятор

## Состав

- `main.py` — CLI, валидация, две детерминированные модели, три роли анализа и оркестратор.
- `example_allocation.json` — пять сумм по направлениям.
- `example_measures.json` — пять мероприятий по правилам датасета.
- `example_report.json` — полный проверенный JSON-вывод режима сумм без API.
- `jury_report.md` — короткий образец доклада для жюри.

Исходные документы: [описание кейса](https://docs.google.com/document/d/1oDZtYnBgbcn_Ii7vleP87hkARJ2HmbXl7Cw_rsCxqpo/edit?usp=sharing), [датасет районов и формула](https://docs.google.com/document/d/1Uc-GdGoKhDY-spu8V50-ZMm33t2CjYLP/edit?usp=sharing).

## Запуск

Нужен Python 3.10+. В каталоге с файлами:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
# В .env укажите настоящий OPENAI_API_KEY
.venv\Scripts\python main.py --input example_allocation.json
.venv\Scripts\python main.py --input example_measures.json
```

Демо без ключа и сетевых вызовов:

```powershell
.venv\Scripts\python main.py --input example_allocation.json --offline
```

Если ключ не задан, программа автоматически использует правила вместо LLM и честно ставит `ai_mode: offline_rules`. При наличии ключа две профильные AI-роли вызываются параллельно через OpenAI Responses API со Structured Outputs, затем вызывается оркестратор. Модель по умолчанию — `gpt-4o-mini`; можно задать `OPENAI_MODEL` или `--model`.

Вывод — JSON в stdout. Невалидный сценарий возвращает причину в stderr и код выхода 2. Суммы и цены здесь **условные**; их можно трактовать как млрд тенге только в игровом интерфейсе. Реальных бюджетных оценок код не содержит.

## Архитектура

```text
JSON → валидатор → чистая математическая модель → фиксированный score
                                           ↓
                              Analytics & Math Engine
                                           ↓
                         Urban Expert  ∥  Social & Risk
                                           ↓
                               Akim Chief Advisor
                                           ↓
                                      JSON отчёт
```

`Analytics & Math Engine` выполняется детерминированно. `Astana Urban Expert` и `Social & Risk Agent` получают уже рассчитанные числа и пишут пояснения, `Akim Chief Advisor` сводит их. LLM не вправе менять score. Социальный риск без источника соцсетей — только модельный прокси, а не измеренное общественное мнение или прогноз протестов.

## Режим сумм (`allocations`)

Пять решений — суммы `xᵢ ≥ 0` для `transport`, `greening`, `social`, `safety`, `services`; `Σxᵢ ≤ 100`. Невалидные суммы, лишние или отсутствующие направления отклоняются. Остаток бюджета не даёт бонуса.

Каждая сфера влияет на два соответствующих показателя района. Все исходные показатели `I[d,k]` взяты из датасета, шкала 0–100, больше — лучше. Для сферы `i`:

```text
uᵢ = 1 − exp(−xᵢ / τᵢ)
deficit[d,i] = 100 − mean(I[d,k] для двух показателей сферы i)
μᵢ = Σd pop[d] · deficit[d,i]
gain[d,i] = Aᵢ · uᵢ · deficit[d,i] / μᵢ
I′[d,k] = clip(I[d,k] + gain[d,sector(k)] + synergy[d,k], 0, 100)
```

`uᵢ` задаёт убывающую отдачу: первая единица вложения полезнее следующей. Множитель дефицита отдаёт больше эффекта району с более слабой стартовой позицией. `A` и `τ` — **демонстрационные**, подлежат калибровке на реальных данных.

| Сфера | `Aᵢ` | `τᵢ` | Целевая доля `qᵢ` |
|:--|--:|--:|--:|
| Транспорт | 24 | 24 | 0.24 |
| Озеленение | 20 | 20 | 0.16 |
| Соцсфера | 24 | 22 | 0.23 |
| Безопасность | 19 | 18 | 0.16 |
| Сервисы | 23 | 24 | 0.21 |

Синергии добавляются к указанному показателю во всех районах и равны `c · √(uᵢuⱼ)`:

| Пара | Показатель | `c` | Городской смысл |
|:--|:--|--:|:--|
| Транспорт + сервисы | T1 | 2.0 | Зимняя проходимость дорог |
| Транспорт + озеленение | E2 | 1.5 | Воздух и мобильность |
| Соцсфера + безопасность | B1 | 2.0 | Безопасная среда у соцобъектов |
| Сервисы + безопасность | C1 | 1.5 | Оперативность и устойчивость ЖКХ |

При `S = Σxᵢ > 0` и `sᵢ = xᵢ/S` штрафы за перекос:

```text
P_concentration = 6 · (S/100) · Σᵢ(sᵢ − qᵢ)²
P_underfunding = 1.5 · (S/100) · Σᵢ max(0, 0.5qᵢ − sᵢ)/(0.5qᵢ)
```

Если `S = 0`, оба штрафа равны нулю. Эти коэффициенты тоже демонстрационные; правило штрафа заставляет явно видеть цену провалов по сферам.

## Общий Astana Quality of Life Score

В обоих режимах веса 10 показателей и районов точно совпадают с датасетом:

```text
D[d] = Σk w[k] · I′[d,k]
D_avg = Σd pop[d] · D[d]
N_crit = число пар (район, показатель) с I′[d,k] < 40
Score = clip(0.7 · D_avg + 0.3 · min_d D[d] − N_crit − P, 0, 100)
```

`P` равен сумме двух штрафов в режиме сумм и нулю в режиме мероприятий. Веса `T1,T2,E1,E2,S1,S2,B1,B2,C1,C2`: `0.10, 0.10, 0.09, 0.11, 0.11, 0.11, 0.09, 0.09, 0.10, 0.10`. Базовый Score — **52.56**. Большой вес слабейшего района снижает стимул улучшать только благополучные районы.

## Режим мероприятий (`measures`)

Этот режим буквально воспроизводит правила второго документа: ровно пять уникальных мероприятий из `M1…M14`, общий бюджет 100, максимум две меры одного направления, район обязателен только для районной меры. Проверяются несовместимости `M1+M3` в любом районе, `M4+M7` и `M5+M13` в одном районе.

Горизонт — 8 кварталов. Для каждого эффекта применяется доля `(8−lag)/8`. Три синергии документа добавляются без масштабирования лагом: `M1+M2` даёт `T1+2` в районе M1, `M10+M12` даёт `B1+2` в районе M10, `M5+M6` даёт `E2+2` в районе M5. Данные затем ограничиваются диапазоном 0–100. Полный каталог и цены находятся в `main.py`.

Пример датасета (`M7 Нура`, `M8 Нура`, `M10 Нура`, `M12`, `M5 Сарыарка`) стоит **95** и даёт **56.54**; это соответствует указанному в документе ориентиру ≈56.5. `marginal_score_if_removed` показывает потерю Score при удалении каждой отдельной меры из готового набора, с учётом исчезновения её синергий; это диагностический контрфактический расчёт, а не повторная проверка правила «ровно пять».

## Ограничения модели

Сценарные коэффициенты режима сумм не оценены на наблюдениях. Каталог и исходные показатели синтетические. Значения не следует выдавать за прогноз реального воздействия бюджетных мер. Для применения в городе нужны фактические расходы, сроки, геоданные, эксплуатационные затраты, зимние показатели и обезличенные обращения жителей.
